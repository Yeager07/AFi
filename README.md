# AFi — Accounting of Finances

Мобильное приложение для учёта и анализа доходов и расходов малого кофейного бизнеса.
Разрабатывается как учебный проект в рамках курса «Визуальное программирование».

## О проекте

### Предыстория

У моего друга — небольшая кофейня. Он сам закупает зерно, платит за аренду,
налоги и зарплату бариста, но постоянно путается в цифрах: сколько ушло
на закупки в прошлом месяце, сколько стоила аренда, сколько нужно отложить
на следующий месяц. Готовые решения (типа «Мой Склад», «Дримкас») либо
слишком дорогие, либо перегружены функциями, которые микробизнесу не нужны.

### Цель

Простое приложение, которое:
- Позволяет за 5 секунд внести трату или доход.
- Показывает, куда уходят деньги, без сложных отчётов.
- Предупреждает о регулярных платежах и подсказывает ожидаемые расходы
  на следующий месяц.

## Целевая аудитория

- Владелец микробизнеса (1–5 сотрудников).
- Работает сам, без бухгалтера.
- Нужен минимум: ввод, категории, наглядность.
- Устройство: Android или iOS (в перспективе — Windows).

## Требования

### Функциональные

#### 1. Ввод и категоризация операций

- Добавление дохода или расхода: сумма, категория, дата, комментарий (опционально).
- **Категории по умолчанию (расходы):**
  - Аренда
  - Закупки (сырьё)
  - Налоги
  - Коммунальные услуги
  - АЗС
  - Транспорт
  - Кафе и рестораны
  - Дом и ремонт
  - Одежда и обувь
  - Подписки
  - Цветы
  - Прочее
- **Категории по умолчанию (доходы):**
  - Выручка
  - Зарплата
  - Прочие поступления
- **Пользовательские категории:** пользователь может добавить свою категорию
  в любой раздел (доходы или расходы) и удалить её. Если к удаляемой категории
  привязаны операции, приложение запрашивает подтверждение и предупреждает,
  что операции останутся, но будут помечены как «Без категории».
- Возможность редактировать и удалять операции.
- Фильтрация по периоду (текущий месяц, прошлый месяц, произвольный диапазон).

#### 2. Визуализация статистики

- **Обе диаграммы доступны всегда, переключаются пользователем:**
  - Круговая — распределение расходов по категориям за выбранный период.
  - Столбчатая — доходы vs расходы по месяцам.
- **Итоговые суммы** за выбранный период:
  - Общий доход.
  - Общий расход.
  - Баланс (доход − расход).
  - Расходы в разбивке по категориям.
- **Период по умолчанию:** с 1-го числа текущего календарного месяца
  до текущей даты (день, в который пользователь смотрит статистику).
  Пользователь может изменить диапазон.

#### 3. Баланс и регулярные платежи

- **Баланс.** Пользователь указывает **начальный** баланс один раз при первом
  запуске. Приложение отображает **текущий баланс** динамически:
  `начальный + сумма доходов − сумма расходов`. Начальный баланс можно
  изменить вручную в настройках (например, при сверке с реальным счётом).
- **Регулярные платежи** — это напоминания, а не автоплатежи:
  - Пользователь добавляет платёж: название, сумма, день месяца.
  - Приложение показывает список предстоящих платежей в текущем месяце.
  - За N дней до даты платежа приходит локальное уведомление.
  - Возможность включить/выключить напоминание для конкретного платежа.
- **Банковские карты в приложении не хранятся.** Списания не производятся.
  Приложение — учётный инструмент, а не платёжный.

#### 4. Прогноз бюджета на следующий месяц

**Алгоритм (гибридный — частотный фильтр + медиана):**

1. Берём 3 последних **полных** месяца (текущий неполный не учитываем).
2. Для каждой категории расходов считаем, в скольких из этих 3 месяцев
   она встречалась, и собираем суммы.
3. Применяем правило:
   - **Встречалась в 3 месяцах** → берём **медиану** трёх значений
     (устойчиво к разовым выбросам в одном из месяцев).
   - **Встречалась в 2 месяцах** → берём **среднее** двух значений
     (медиана из двух — это и есть среднее).
   - **Встречалась в 1 месяце** → **не включаем** в прогноз
     (разовые крупные траты не повторятся).
4. Сумма значений по всем «зачётным» категориям = прогноз расходов
   на следующий месяц.
5. Результат показывается таблицей: категория → значение →
   включена в прогноз (да/нет).

**Почему медиана, а не среднее:** пример — расходы на «Закупки» за 3 месяца
составили 10 000, 12 000 и 80 000 ₽ (в одном месяце закупили дорогое
оборудование). Среднее = 34 000 ₽ (завышено), медиана = 12 000 ₽ (реалистично).

**Почему не ML:** выборка в 3 точки данных слишком мала для обучения.
Простая эвристика с устойчивой статистикой даёт более предсказуемый результат.

### Нефункциональные

- **Локальное хранение.** Все данные — в SQLite на устройстве, без сервера.
- **Работа офлайн.** Приложение не требует интернета.
- **Кроссплатформенность.** Приоритет — Android и iOS. Windows — после
  стабилизации мобильной версии.
- **Простой UI.** Минимум экранов, крупные кнопки, никаких вложенных меню
  глубиной 3+ уровня. Пользователь должен находить нужный экран за ≤2 нажатия.

## Технологический стек

| Компонент | Технология | Почему |
|---|---|---|
| Платформа | .NET MAUI (.NET 8) | Один язык (C#) со всеми прошлыми проектами, кроссплатформенность |

| Прогноз | Встроенная математика | Эвристика на основе частотного анализа, без ML |

## Этапы разработки

Проект разбит на 5 этапов. **Каждый этап — законченная, тестируемая единица.**
Переход к следующему только после того, как текущий работает.

### Этап 1. Скелет приложения + ввод транзакций

- Пустое MAUI-приложение запускается на Android.
- Локальная SQLite-база с таблицами `Transaction`, `Category`, `RecurringPayment`.
- Категории по умолчанию засеяны при первом запуске.
- Один экран: форма добавления операции + список последних 10 операций.
- **Как проверить:** добавил расход → он появился в списке → закрыл приложение →
  открыл → операция на месте.

### Этап 2. Управление операциями и категориями

- Редактирование и удаление операций.
- Фильтрация списка по периоду.
- Экран управления категориями: добавить свою, удалить с подтверждением,
  если к категории привязаны операции.
- Карточка «Текущий баланс» на главном экране.
- **Как проверить:** отредактировал операцию → баланс обновился; добавил
  свою категорию → она доступна в форме; удалил её → операция осталась,
  но категория отображается как «Без категории».

### Этап 3. Визуализация

- Экран статистики с переключателем типа диаграммы (круговая / столбчатая).
- Итоговые карточки: доход, расход, баланс, разбивка по категориям.
- Выбор периода, по умолчанию — с 1-го числа текущего месяца по сегодня.
- **Как проверить:** ввёл 5 расходов в 3 категориях → круговая диаграмма
  отражает пропорции; переключил на столбчатую → видно доходы vs расходы
  по месяцам.

### Этап 4. Регулярные платежи и напоминания

- Экран «Регулярные платежи»: список, добавление, редактирование.
- Планирование локальных уведомлений за 2 дня до даты.
- Переключатель «напоминание включено/выключено» для каждого платежа.
- **Как проверить:** добавил платёж на завтра → получил уведомление
  в назначенное время; выключил напоминание → уведомление не приходит.

### Этап 5. Прогноз бюджета

- Экран «Прогноз»: расчёт по алгоритму из требований (гибрид частотного
  фильтра и медианы).
- Таблица: категория → значение → включена в прогноз (да/нет).
- Итоговая сумма прогноза.
- **Как проверить:** ввёл данные за 3 месяца, где категория «Аренда»
  встречается все 3 месяца, а «Дом и ремонт» — только в 1 → в прогнозе
  есть «Аренда» и нет «Дом и ремонт».

## Ограничения (не входит в MVP)

- Многопользовательский режим.
- Синхронизация с облаком.
- Хранение данных банковских карт и автоплатежи (сознательно исключено).
- Экспорт в Excel/CSV.
- Бюджеты на категорию с лимитами.
- Импорт выписок из банка.
- Авторизация.
- Версия для Windows (после мобильной).
- Сезонность (кофейни летом и зимой имеют разные расходы — пока не учитываем).
- Многомерные модели прогноза (Holt-Winters, ARIMA) — избыточны для 3 точек.

Всё это — «на будущее», если проект получит развитие.
