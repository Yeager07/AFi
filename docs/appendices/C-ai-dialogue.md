# Приложение C. Примеры диалогов с ИИ

В этом приложении собраны шесть наиболее показательных диалогов 
с генеративной моделью. Каждый пример демонстрирует конкретный приём 
работы с ИИ: планирование, выбор из вариантов, отладку через логи, 
рефакторинг.

Формат: **запрос** → **ответ ИИ (сокращённо)** → **что сделали**.

---

## C.1. Планирование Этапа 5 — выбор алгоритма прогноза

**Контекст:** нужно реализовать прогноз бюджета на следующий месяц.

### Запрос

> Давай сделаем прогноз бюджета. Какие есть варианты алгоритма? 
> Хочу сначала посмотреть, что можно, потом выберем. Не пиши код.

### Ответ ИИ (сокращённо)

> Предлагаю 6 вариантов, от простого к сложному:
>
> 1. **Среднее арифметическое** — сумма всех расходов категории за 3 месяца / 3.
>    Просто, но чувствительно к выбросам.
>
> 2. **Частотный фильтр + среднее** — включаем только категории, 
>    встречавшиеся 2+ раз. Просто и отсекает разовые траты.
>
> 3. **Взвешенное скользящее среднее** — последним месяцам больший вес. 
>    Ловит тренды, но не защищает от выбросов.
>
> 4. **Медиана** — вместо среднего берём серединное значение. 
>    Устойчиво к выбросам.
>
> 5. **Усечённое среднее** — отбрасываем min и max, считаем среднее 
>    по оставшимся. Нужно 4+ точек, а у нас 3.
>
> 6. **Экспоненциальное сглаживание (Holt's)** — настоящий метод 
>    прогнозирования временных рядов. Раскрывается на 10+ точках.
>
> Моя рекомендация — **комбинация 2 + 4**: частотный фильтр отсекает 
> разовые траты, медиана защищает от выбросов внутри регулярных. 
> Работает на малой выборке.

### Что сделали

Обсудили варианты, я согласился на гибрид 2+4. ИИ написал алгоритм, 
мы реализовали в `ForecastService`. Позже добавили к нему тесты 
на реальных данных.

**Польза:** увидели ландшафт возможных решений, осознанно выбрали 
компромисс между простотой и точностью.

## C.2. Тематизация — отказ от XAML-словарей

**Контекст:** нужно реализовать 5 тем оформления.

### Запрос

> Давай сделаем 5 тем: Светлая, Тёмная, Космос, Хеллоуин, Аркадная. 
> Как лучше реализовать переключение?

### Ответ ИИ

> Классический подход — использовать `ResourceDictionary` для каждой 
> темы в XAML-файлах:
>
> ```
> Themes/LightTheme.xaml
> Themes/DarkTheme.xaml
> Themes/SpaceTheme.xaml
> ```
>
> При смене темы — удалять старый словарь из `Application.Resources.MergedDictionaries` 
> и добавлять новый. Все элементы на `DynamicResource` перекрасятся 
> автоматически.
>
> Вот код `ThemeService`:
>
> ```csharp
> private static ResourceDictionary? LoadDictionary(string name)
> {
>     return new ResourceDictionary
>     {
>         Source = new Uri($"Themes/{name}Theme.xaml", UriKind.Relative)
>     };
> }
> ```
>
> Тема применяется через `Application.Current.Resources.MergedDictionaries.Add(...)`.

### Что сделали

Реализовали по этому рецепту. **Сборка упала** с ошибкой:

```
error: The 'LightTheme.xaml' start tag on line 1 does not match 
the end tag of 'ResourceDictionary'.
```

Я скинул ошибку ИИ. Обсудили причины:
1. Файлы `.xaml` не попадали в сборку из папки `Themes/` (вне `Resources/`).
2. `MauiXamlInflator = SourceGen` в .NET 10 не находил словари по 
   относительному пути.
3. `ResourceDictionary.Source` в рантайме возвращал пустые словари.

**Второй запрос:**

> XAML-словари не работают в .NET 10 из-за SourceGen. Какие есть 
> альтернативы?

### Ответ ИИ

> Есть три варианта:
>
> **A. Переместить в `Resources/Themes/`** — там MAUI автоматически 
> включает XAML в сборку. Но с SourceGen всё равно могут быть проблемы.
>
> **B. Программная тематизация** — цвета прямо в C# через `Dictionary<string, string>`. 
> Никаких XAML-файлов. Работает гарантированно.
>
> **C. Комбинация** — XAML-словари только для статичных ресурсов, 
> цвета — программно.
>
> Я рекомендую **B** — это самый надёжный путь, если приоритет 
> — работа в любых версиях .NET.

### Что сделали

Перешли на **программную тематизацию**. `ThemeService` теперь хранит 
5 палитр прямо в C#:

```csharp
private static readonly Dictionary<string, string> LightTheme = new()
{
    ["PrimaryColor"]        = "#512BD4",
    ["PageBackgroundColor"] = "#F3F3F3",
    // ...
};
```

Применение — через `Application.Current.Resources[key] = color`. 
Все элементы на `DynamicResource` перекрашиваются автоматически. 
**Работает без сбоев во всех 5 темах.**

**Польза:** ИИ предложил рабочий подход, но после первой неудачи 
быстро переключился на альтернативу. Диалог занял 2 итерации вместо 
долгих попыток «починить XAML».

## C.3. Баг с TouchBehavior — почему не заработало

**Контекст:** хотим сделать мультивыбор через долгое нажатие.

### Запрос

> Как в MAUI отловить долгое нажатие на элемент списка? 
> Хочу, чтобы по лонг-тапу включался режим выбора.

### Ответ ИИ

> Используй `TouchBehavior` из `CommunityToolkit.Maui`:
>
> ```xml
> <Border.Behaviors>
>     <toolkit:TouchBehavior
>         LongPressCommand="{Binding StartSelectionCommand}"
>         LongPressCommandParameter="{Binding .}"
>         LongPressDuration="600" />
> </Border.Behaviors>
> ```
>
> Убедись, что пакет установлен и зарегистрирован:
> ```csharp
> builder.UseMauiCommunityToolkit();
> ```

### Что сделали

Установили `CommunityToolkit.Maui 14.1.0`, добавили поведение. 
**Не работает** — ни тап, ни долгое нажатие не срабатывают.

**Второй запрос:**

> TouchBehavior не реагирует на жесты, обычный тап тоже не работает. 
> Вот код XAML.

### Ответ ИИ

> Возможные причины:
>
> 1. **Конфликт с `SwipeView`.** Если `Border` внутри `SwipeView`, 
>    жесты перехватываются свайпом. Убери `SwipeView` — проверь.
> 2. **Конфликт с `TapGestureRecognizer`.** Если у `Border` уже есть 
>    `TapGestureRecognizer`, он перехватывает событие. Попробуй убрать 
>    `TapGestureRecognizer` и использовать только `Command` из 
>    `TouchBehavior`.
> 3. **`x:Reference` в `Behaviors`.** Внутри `DataTemplate` привязки 
>    к странице через `x:Reference` иногда не разрешаются. Попробуй 
>    `RelativeSource`.

### Что сделали

Попробовали все три варианта по очереди. Ни один не сработал 
(это особенность MAUI 10 + CommunityToolkit 14.x). 

**Третий запрос:**

> Ничего не помогает. Давай откажемся от TouchBehavior. Какие 
> есть альтернативы для мультивыбора?

### Ответ ИИ

> Простой и надёжный способ — кнопка «Выбрать» рядом с заголовком 
> списка. Она переключает `IsSelectionMode` в VM, у карточек 
> появляются чекбоксы, тап по карточке переключает выбор.
>
> Работает во всех версиях MAUI. Не зависит от TouchBehavior.

### Что сделали

Отказались от лонг-тапа. Реализовали через кнопку. **Работает 
стабильно на всех устройствах.**

**Польза:** диалог показал, что не все официальные рекомендации 
работают на практике. Важно вовремя остановиться и выбрать 
более простое решение.

## C.4. Баг с уведомлениями — как logcat помог

**Контекст:** напоминания не приходят, хотя код выглядит корректно.

### Запрос

> Уведомления не приходят. Вот код ReminderService. Что не так?

### Ответ ИИ

> С кодом вроде всё в порядке. Давай проверим:
>
> 1. **Разрешения.** На Android 13+ нужно `POST_NOTIFICATIONS`, 
>    на Android 12+ — `SCHEDULE_EXACT_ALARM`. Проверь `AndroidManifest.xml`.
> 2. **Режим планирования.** Если используешь `InexactAllowWhileIdle`, 
>    система может задерживать уведомление на 15–30 минут через `WorkManager`.
>    Для точных уведомлений нужен `ExactAllowWhileIdle`.
> 3. **Оптимизация батареи Samsung.** Samsung очень агрессивно «душит» 
>    фоновые приложения. Убедись, что приложению разрешена работа 
>    в фоне.
>
> Проверь через `adb logcat`:
> ```
> adb logcat | Select-String "Notification", "Alarm"
> ```

### Что сделали

Проверили логи. Увидели, что `InexactAllowWhileIdle` действительно 
используется, но уведомление не приходит. В логах было видно 
`AlarmManager: setExactAndAllowWhileIdle`, но только для других 
приложений.

**Второй запрос:**

> Логи показали, что разрешение `SCHEDULE_EXACT_ALARM` не выдано. 
> Как его запросить?

### Ответ ИИ

> На Android 12+ это разрешение не выдаётся автоматически. 
> Нужно запросить вручную:
>
> ```csharp
> if (!alarmManager.CanScheduleExactAlarms())
> {
>     var intent = new Intent(Settings.ActionRequestScheduleExactAlarm);
>     intent.SetData(Android.Net.Uri.Parse($"package:{context.PackageName}"));
>     intent.AddFlags(ActivityFlags.NewTask);
>     context.StartActivity(intent);
> }
> ```
>
> Откроется системный экран «Будильники и напоминания», где пользователь 
> должен включить переключатель для твоего приложения.

### Что сделали

Добавили `RequestExactAlarmPermission` в `ReminderService`. При старте 
приложения система показала экран «Будильники и напоминания», 
я включил переключатель. **Уведомления стали приходить точно 
в назначенное время.**

**Польза:** логи Android указали точное место проблемы. Без них 
пришлось бы перебирать все возможные причины.

## C.5. Баг мультивыбора — почему операции не удалялись

**Контекст:** после нажатия «Удалить» в модалке ничего не происходит.

### Запрос

> Мультивыбор работает — операции выбираются, счётчик растёт. Но при 
> нажатии «Удалить» в модалке подтверждения ничего не происходит. 
> Модалка закрывается, но операции остаются.

### Ответ ИИ

> Возможные причины:
>
> 1. **`TrySetResult` не срабатывает.** В `ThemedConfirmPage` метод 
>    `OnAcceptClicked` — сначала `PopModalAsync`, потом `TrySetResult`. 
>    Если `PopModalAsync` не возвращает управление, `TrySetResult` 
>    никогда не выполнится.
>
> **Фикс:** поменять порядок — сначала `TrySetResult`, потом `PopModalAsync`.
>
> ```csharp
> private async void OnAcceptClicked(object? sender, EventArgs e)
> {
>     _tcs.TrySetResult(true);   // сначала результат
>     
>     try { await Navigation.PopModalAsync(); }
>     catch { /* тихо */ }
> }
> ```
>
> 2. **`_selectedIds` пуст.** Проверь, что `HashSet<int>` заполняется 
>    при выборе.
> 3. **`IsBusy` = true.** Если флаг поднят другой операцией, 
>    `DeleteSelectedAsync` выходит в первой строке.

### Что сделали

Поменяли порядок в `ThemedConfirmPage`. **Заработало** — операции 
удалились сразу.

**Польза:** ИИ точно указал причину, потому что уже сталкивался 
с этой проблемой (в ActionSheet мы её уже фиксили). Диалог занял 
одну итерацию.

## C.6. Фикс категории в Истории — рефакторинг через Equals

**Контекст:** в Истории не работает фильтрация по категории.

### Запрос

> В Истории не работает фильтр по категории. Когда выбираю категорию 
> в Picker-е — список не обновляется. С чем связано?

### Ответ ИИ

> Скорее всего, проблема в **сравнении объектов**. Смотри цепочку:
>
> 1. `HistoryPage.OnAppearing` вызывается при каждом возврате 
>    с модалки Picker-а.
> 2. Внутри `LoadCommand` → `ReloadFiltersAsync` пересобирает 
>    `CategoryFilterItems.Clear()` + заново заполняет коллекцию.
> 3. Все экземпляры `CategoryFilterItem` — **новые объекты**.
> 4. Возвращаемся в `ThemedPicker.OnTapped` → `SelectedItem = result`.
> 5. Обработчик `Picker → VM` пытается найти `result` в новой 
>    коллекции через `IndexOf` → возвращает **-1**.
> 6. `SelectedCategoryIndex` не меняется → список не перезагружается.
>
> **Фикс** — две правки:
>
> **A. Не пересобирать фильтры при каждом возврате:**
> ```csharp
> private bool _filtersLoaded;
> 
> public async Task LoadAsync()
> {
>     if (!_filtersLoaded)
>     {
>         await ReloadFiltersAsync();
>         ApplyPendingCategoryFilter();
>         _filtersLoaded = true;
>     }
>     await ReloadAsync();
> }
> ```
>
> **B. Переопределить `Equals` / `GetHashCode` в `CategoryFilterItem`:**
> ```csharp
> public override bool Equals(object? obj)
> {
>     if (obj is not CategoryFilterItem other) return false;
>     return FilterName == other.FilterName;
> }
> 
> public override int GetHashCode() => FilterName?.GetHashCode() ?? 0;
> ```
>
> Тогда `IndexOf` найдёт эквивалентный элемент, даже если это 
> другой экземпляр.

### Что сделали

Применили оба фикса. **Фильтр заработал**.

**Польза:** ИИ разобрал всю цепочку от `OnAppearing` до `IndexOf` 
и указал **две** причины. Одна без другой не помогла бы — фильтры 
могли пересобираться в других сценариях (например, при возврате 
из Статистики).

## C.7. Итоговые наблюдения

**Что общего у всех шести диалогов:**

1. **Короткий запрос — конкретная проблема.** Не «сделай всё сразу», 
   а «вот баг, вот контекст, что не так?».
2. **Прикладываю логи, скриншоты, код.** Чем больше контекста — 
   тем точнее ответ.
3. **Уточнения после ошибок.** Первый ответ ИИ — не всегда правильный. 
   Второй и третий часто дают нужный результат.
4. **Отказ от сложного в пользу простого.** Когда один подход 
   не работает — выбираем альтернативу, а не «дожимаем».

**Метрика по этим шести диалогам:**

| Диалог | Итераций | Результат |
|---|---|---|
| C.1 Планирование прогноза | 1 | Гибрид 2+4 |
| C.2 Тематизация | 2 | Программная тематизация |
| C.3 TouchBehavior | 3 | Отказ, кнопка «Выбрать» |
| C.4 Уведомления | 2 | ExactAllowWhileIdle |
| C.5 Мультивыбор | 1 | Смена порядка в модалке |
| C.6 Фильтр категории | 1 | `_filtersLoaded` + `Equals` |

**Средняя скорость решения:** 1–2 итерации. Дольше всего заняла 
работа с `TouchBehavior` (3 итерации + отказ).

**Главный вывод:** самое ценное в работе с ИИ — **быстрая итерация**. 
Запрос → ошибка → уточнение → фикс. То, что обычный разработчик 
искал бы часами (например, конфликт `TouchBehavior` с `SwipeView`), 
здесь решалось за 2–3 запроса.
