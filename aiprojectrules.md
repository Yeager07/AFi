# Правила работы ИИ-ассистента в проекте AFi

## Общие

1. Объясни, что собираешься сделать, и попроси подтверждения ПЕРЕД написанием кода.
2. Сначала предлагай простейшее решение. Усложняй только при явной необходимости.
3. Используй модули (файлы), а не один большой файл. Один класс — один файл.
4. Не пиши дублирующийся код — ищи существующие решения в кодовой базе.
5. Вноси только запрошенные изменения. Не рефактори «попутно».

## Стиль кода C#

- Nullable reference types включены, `#nullable enable` по умолчанию в csproj.
- Имена классов, методов, свойств — на английском, PascalCase / camelCase.
- Комментарии — на русском, только там, где логика неочевидна.
- Async-методы заканчиваются на `Async`, используют `CancellationToken` где возможно.
- MVVM: ViewModels наследуются от `ObservableObject` (из CommunityToolkit.Mvvm).
- DI: все сервисы регистрируются в `MauiProgram.cs`.

## Работа с UI

- XAML-файлы — только разметка. Никакой логики в code-behind, кроме вызовов ViewModel.
- Цвета, шрифты, размеры — через `Resources/Styles/`. Не хардкодить в XAML.
- Поддержка светлой и тёмной темы — обязательно для новых экранов.

## Git и процесс

- После каждого завершённого этапа — коммит с сообщением Conventional Commits:
  `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`
- После каждого этапа — скриншот в `docs/screenshots/` с номером и описанием.

## Что НЕ делать

- Не устанавливать новые NuGet-пакеты без явного согласования.
- Не менять структуру папок без обсуждения.
- Не оптимизировать преждевременно.
- Не добавлять серверную часть, облако, аутентификацию — проект строго локальный.
