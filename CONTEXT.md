AFi — Контекст проекта для передачи (октябрь 2026)
1. Что это за проект
AFi (Accounting of Finances) — Android-приложение для учёта доходов и расходов малого бизнеса (изначально для кофейни друга, сейчас — для личного пользования). Полностью локальное, работает офлайн, данные в SQLite.

Стек:

.NET 10 + .NET MAUI + C# 12

SQLite через sqlite-net-pcl

MVVM через CommunityToolkit.Mvvm (Source generators: [ObservableProperty], [RelayCommand])

Диаграммы — Microcharts.Maui + SkiaSharp

QR — BarcodeScanning.Native.Maui (ML Kit под капотом) + ZXing.Net.Maui (fallback)

Уведомления — Plugin.LocalNotification (ExactAllowWhileIdle)

Сканирование штрих-кодов — ZXing.Net.Maui

Платформа: Android (приоритет), iOS/Windows в перспективе. SupportedOSPlatformVersion = 23.0 (требование ML Kit).

2. Как ведётся работа
Совместная разработка с ИИ-ассистентом по методологии «Золотые правила» (12 практик работы с генеративными моделями из учебного курса «Визуальное программирование»). Ключевые правила, которые используются каждый день:

Vibe PMing — сначала спецификация в README, только потом код.

Простой стек — минимум зависимостей, каждая новая обоснована.

Правила и документация ИИ — в репозитории есть .aiprojectrules.md, версии библиотек зафиксированы, ссылки на актуальную документацию.

Не кодировать сразу — сначала план, согласование, потом реализация.

Варианты решений — для сложных задач ИИ предлагает 2–3 подхода, выбираем простой.

Дробить на шаги — каждый этап разбивается на 3–6 подшагов с отдельным тестированием.

Изображения для контекста — скриншоты помогают ИИ понять баг или UX.

Тестировать беспощадно — после каждого подшага сборка + ручной тест на реальном устройстве (Samsung Galaxy A34).

Не бояться откатов — если ИИ сломал работающее, откатываемся к последнему коммиту.

GitHub + Conventional Commits — после каждого этапа коммит (feat:, fix:, refactor:, perf:, docs:).

Голосовой ввод — не используется (VS Code, нет Superwhisper).

Просить ИИ объяснять код — для понимания архитектуры и защиты.

Стиль кода (закреплено в .aiprojectrules.md):

Nullable reference types включены

Имена — английский, PascalCase / camelCase

Комментарии — русский, только там где логика неочевидна

Async-методы заканчиваются на Async

MVVM: ViewModels наследуются от ObservableObject

DI: все сервисы регистрируются в MauiProgram.cs

XAML — только разметка, никакой логики в code-behind

Цвета, шрифты, размеры — через DynamicResource

Один класс — один файл

Важно: пользователь просит всегда скидывать полные файлы с комментариями-разделителями, не сокращать, не убирать структуру. Это правило строгое, нарушение раздражает. Если правка в файле — даётся целиком, а не фрагмент.

6. Что планируем делать дальше — Собственная OCR-модель
Контекст
Сейчас зависим от proverkacheka.com (15 запросов/сутки бесплатно). Для коммерческого использования (Google Play / RuStore) это не подходит — нужен свой OCR или API крупного ОФД. Пользователь выбрал изучение Computer Vision / OCR как учебную задачу + вложение в проект.

Фаза 1 (до 30 октября 2026) — Теория
Пользователь изучает теорию OCR по отдельному плану в другом чате:

Основы Computer Vision (CNN, transfer learning)

OCR-движки (Tesseract классика, PaddleOCR / EasyOCR нейросети, CRNN, TrOCR)

Layout Understanding (LayoutLMv3, Donut, датасеты SROIE / CORD)

Пайплайн для чеков — выбор подхода

Метрики (CER, WER, F1 для полей)

Итог к 30 октября: конспект-шпаргалка, которую пользователь принесёт в этот чат.

Фаза 2 (после 30 октября) — Практика
Выбранный пайплайн: Фото → PaddleOCR (текст + координаты) → LayoutLMv3 (классификация токенов: NAME / PRICE / QUANTITY / TOTAL / OTHER) → пост-обработка → JSON.

Что делаем в новом чате:

Окружение: Python, Jupyter, установка PaddleOCR, PyTorch, transformers (Hugging Face).

Датасет: собрать 50–100 реальных чеков (Монетка, Магнит, Пятёрочка), разметить через Label Studio или CVAT.

OCR-пайплайн: прогнать все чеки через PaddleOCR, получить текст + координаты.

Fine-tuning LayoutLMv3: обучить модель классифицировать токены по полям.

Пост-обработка: собрать токены в позиции (Name + Quantity + Price + Total).

Интеграция в AFi: обернуть пайплайн в FastAPI-микросервис или использовать ONNX Runtime на мобильном. Пока не решено — оффлайн на устройстве (тяжело) или облачный микросервис (проще).

Что важно понимать:

Это не замена текущего QR-сканера. QR (с proverkacheka.com или ОФД) остаётся основным способом — 100% точность.

OCR — fallback и учебный проект. Результаты OCR будут с ошибками, пользователь будет дорабатывать вручную.

Tesseract окончательно закрыт как вариант — слишком плохо работает на длинных чеках.

Первый шаг в новом чате: пользователь приносит конспект → совместно разворачиваем Python-окружение → ставим PaddleOCR → прогоняем на одном чеке → смотрим качество → решаем по LayoutLMv3.
